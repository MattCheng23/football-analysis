### 小红书发布线·★标题必须走 CDP 真实输入（2026-09-20 实证·补记9）

**症状**：编辑已发布笔记时，正文更新成功、**标题没变**——出现「正文新、标题旧」的**半更新**。
实测：0919 复盘编辑后，正文已是「001–019 共19场…方向13/19」，标题仍是旧的「方向中12，比分中8」。

**根因**：标题是 React 受控 input。用 `原生 value setter + dispatch('input')` 时，
**DOM 里 value 确实是新值**（所以回读校验会通过、看不出问题），但**React 的受控 state 没吃到**，
提交时按旧 state 写入 ⇒ 静默失败。正文走的是 `execCommand`（真实编辑命令），所以不受影响。

**修法**：标题改用 **CDP 真实输入** ——
`evaluate` 里 `input.focus()` + `setSelectionRange(0, len)`（全选），
再 `cdp Input.insertText {text: 新标题}`（等价真人键入），最后回读 `input.value` 与目标逐字比对。
已落地在 `wb_fill.py::fill_title_cdp()`，**回读不一致直接非 0 退出**（禁静默通过）。

**通用教训**：★**「DOM 值对了」≠「应用收到了」**。React 受控组件上做程序化写入，
回读 DOM 只能证明你写进去了，不能证明它进了 state；关键字段要么用真实输入事件（CDP），
要么在**提交后回查服务端**（本线固定做法：重开编辑页读回 + 下载服务端图比对）。
