## 三、结论：**在"判定"上，初稿与反复过审的终稿几乎打平**

1. **改判＝掷硬币**：全量 36 场改判，改对 17 / 改错 17（维度 +25 / −24），**净 +1 维 ≈ 0**。单批波动极大：最好 +7（9/6）、最差 −5（8/24）、−4（9/11）。**改判不创造期望收益，只放大方差。**
2. **过审唯一的真实增益来自"把场次补齐"（+10 维）**——即票面完整性，而不是判定优化。
3. **"高强度"的绝大部分工作量并不改判定**：9/9 批做了「ht 全因素重审 + alerts 重写 6 条 + 冷门/7+/高价值概率补全」＝3 个互异版本、**0 场改判、净 0**；8/23 批 29 个互异版本也只改判 7 场（净 −3）。→ **版本数（编辑强度）与命中收益不相关**。
4. **修订强度分组的净收益无规律**（互异版本 1–3：+0.0pp｜4：+2.5pp｜5+：+1.9pp）→ 支持"多改不等于改好"。

## 六、局限与置信度

- git 提交节奏为"每日 11:00 + 显式提交"，**当天晚间改版可能不在 git 里**（0911 批至今未提交）→ 该两批用备份链/HANDOFF 补齐；其余批次若存在"未提交的当晚报改"则未被计入。
- 初稿定义＝最早可得的版本；对部分批次该版本可能是"草稿中期"，故"补齐场次 +10 维"中含票面补全成分（已单列）。
- 全量 281 场 / 1152 判定，净差 +11 维（+1.0pp）；单批波动 −5~+10 维 → **结论"改判零期望"比"过审无价值"更准确**：价值在 A 类，风险在 B 类。
