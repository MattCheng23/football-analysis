## 🔴 致命级（违反=效率事故）
1. **PowerShell 内联 python -c / node -e**（GBK 解析必 ParserError/UnicodeEncodeError）→ 一律 write 文件再执行
2. **edit/write 前未 read**（file changed / 覆盖未读）→ 先 read 再改
3. **data.js 等 UTF-8 文件中文字符串内嵌半角引号** → 用「」全角
4. **subprocess 无 encoding="utf-8"** → 中文必乱码
5. **修改后不跑验证链**（node --check → check_batch_full → bump → deploy → 线上 curl）→ 改了=没改；**验证链补全：node --check 对 `},,` 稀疏数组会通过→必须加 hole_guard.py（双逗号+元素数）**
6. **解析接口响应前先 dump 单对象全部 key**（禁猜字段名：type 是 `Goal` 大写/time 非 minute 这类坑 9/7 连踩）→ 0 命中先查速查表字段名节
7. **内联 python -c/node -e 的变种也要禁**：含中文/正则/JSON/多语句的一切脚本=write 文件（9/7 又犯 3 次 GBK/引号/ParserError——"快速迭代"不是豁免理由）
8. **自动计算列必须渲染抽查**（9/7 017 ou 双档 bug 实证）：app.js 的 ou 命中判定只正则第一档（`3·4+4·5` 只判 3·4→5 球误❌）——**"渲染页有内容"≠"每列语义正确"**；WB 验证必须抽查自动计算列（ou/比分 topOf 等）具体值；修复后对全批勾稽（本次 001-017 逐列核对后全绿）
9. **半角引号埋进 data-review/data.js 文本=node --check 必炸**（9/7 017 text 里 `"法兰克福..."` → Unexpected identifier）→ 中文字符串内引号一律「」；修复路径=回滚备份重跑（勿手工单点改）

## 🟠 高频级（每次操作前 10 秒扫）
1. **动手三问**：①做过吗（查 key 记忆/文档/缓存/脚本）②有现成脚本吗（_tmp_football/*.py）③能一次做对吗（先预览断言）
2. **批量修改脚本=幂等三件套**：new 已在则 SKIP / count==1 断言 / ast.parse 后写盘
3. **old 串复制=重新 read 实际字节**（read 显示可能吞引号/转义；\* 类反斜杠单写；可疑字符用 chr() 构造）
4. **WebBridge**：JSON 唯一文件+curl --data-binary @file；可用 tool 先 list（status 不存在/list_tabs 存在）；navigate 后验证队名
5. **检查工具 WARN 一次裁决**（摇摆=浪费；冲突看裁决表；用户拍板优先；摇摆超 2 次=停下读本库）
