# 工作组派活模板（2026-08-25 v1→v2·组长每次派活复制填场次即可）

> 用法：每个岗位下发时=先让它读「工作组方法论卡 + 岗位卡」→ 再按下方模板填场次/文件路径。
> 原则：**任务给完整上下文**（成员不共享主会话），产出必须落文件（不靠对话记忆），验收=文件质量。
> **v2 三大升级（2026-08-25，001 转述失真事故后蒸馏）**：①**禁止组长转述场次情报**——一律指向 data.js 源行号让成员自读原文（转述=信息失真事故根源：001 的"0-0"被转述给 qc 导致其"必须改"判断建立在错误前提上）；②成员输出末尾加**自检行**；③analyst 输出加 **META 机器可读行**（组长/脚本自动结构化，免手工合并）。

## 组长派活前置（每次必做）
1. 确定本批场次清单 + **情报来源=data.js 段行号**（如"8/25 段 1846-1900 行"），**把行号给成员而非复述内容**；如需摘要仅给"指向"，逐字段以原文为准
2. 按流水线排期：scout+loader **并行**先发 → analyst 半批出活即派 qc（管道化，不整批等）→ qc → 组长裁决 →（用户审批）→ archivist
3. 每岗位下发时附：①两份卡路径 ②任务模板 ③输出文件路径 ④验收要点

## 模板 1：scout（情报员）—— 并行批处理
```
【scout 任务·<批次>】先读两份卡。核查对象=<场次清单>。
⚠️ 情报获取：用 read 工具读 data.js <批次段行号> 原文（每场完整 logic 都在里面），**禁依赖组长转述**；转述与原文冲突时以原文为准并标注。
核查维度：伤停/停赛（逐人+位置+双源）/转会离队新援/首发预测/天气开赛当地时刻（open-meteo+FotMob 双源，温度+降水概率+量 mm）/H2H 近 10 次全量/战意/主帅/阵型/裁判草皮。
输出：workgroup\scout_<批>_<日期>.md —— 每场【三态结论+证据级别+来源+日期】，⚠️冲突情报单列（与预测冲突且高级别的，组长必看）。
自检行：本报告数据来源=原文自读（行号）？与组长预测的冲突点已全部列出？
```

## 模板 2：loader（装载员）—— 并行批处理
```
【loader 任务·<批次>】先读两份卡。装载 <场次 matchId 清单 或日期接口>。
每场交付：matchDetails 全量（status/weather/teamForm 逐场/h2h 全史≥10 次/unavailable 逐人+type/formation/Stadium surface/Referee 罚牌/积分榜）或 WebBridge SSR；自检后输出 workgroup\loader_<批>_<日期>.md + 原始 json —— 含"缺口清单"（哪项没拿到），不给残缺数据去猜。
自检行：字段完整性已自检（h2h≥10 次/weather/unavailable 逐人/formation/surface/Referee）？缺口清单为空或已说明？
```

## 模板 3：analyst（分析员）—— 逐场或分批独立推演
```
【analyst 任务·<批次>】先读两份卡。情报=read data.js <批次段行号> 原文自读（禁转述）。按岗位卡结构独立五维推演（候选，非最终）：评级+方向（R426）/带判定（可跑 zoned_predict→lambda_est --band→poisson_top/ht_top，参数从 logic 提炼；产量 λ 优先）/比分 TOP3（每项独立路径+净档）/ht TOP3/ou 双轨/与组长差异点（证据链）/双向冲突。
输出：workgroup\analyst_<场>_<日期>.md。
**每场结尾必须加机器可读行（格式固定）**：META|no|dir 方向|scores a-b/c-d/e-f|ht x/x/x|ou X·Y|grade 级|diff 简述
自检行：带判定跑过工具？差异点给了证据链？双向冲突摆出了？
```

## 模板 4：qc（质检员）—— 定稿后反向挑错（先读 analyst 报告再独立复核）
```
【qc 任务·<批次>】先读两份卡；再读 analyst 报告（workgroup\analyst_*.md 对应场次）后做**独立反向挑错**——8 问（①R426②带-比分-ou③含平有平项④A级条件⑤画像匹配⑥ht 方向占满+TOP1⑦λ 产量校准优先⑧红黑榜+冷门联动），逐场【问题/等级（必须改or建议确认or核过无误）/证据/建议】+**新增盲区**（analyst 没发现的）+对 analyst 分歧的独立判定（同意/部分同意/反对+理由）。
⚠️ 前提自检：组长给的情报可能有转述误差——**先以 data.js 原文核对每场预测字段**（线上=源文件为准），发现前提矛盾最先标注（"前提矛盾"条目）。
输出：workgroup\qc_<批>_<日期>.md。
自检行：前提已按原文核对？8 问逐项回答了？同意/反对 analyst 的理由明确？
```

## 模板 5：archivist（记录员）—— 收尾（每批必跑）
```
【archivist 任务·<批次>】归档复盘记录（stats/results 摘要+五维命中+错因）+**成员质量反馈**（模板）：
1. scout 情报：哪些被证实高价值/哪些误报（配额/失真/无用）
2. analyst 推演：差异点中被证实/被证否的（精确到场次）
3. qc 挑错：必须改项中真命中/空拳；新盲区是否有价值
4. 建议：下批派活 prompt 应加什么/删什么（写回岗位卡备注区）
输出：workgroup\archive_<批>_<日期>.md（反馈写回岗位卡 rs 备注）。
自检行：每条反馈可溯源（谁/什么/结果）？
```

## 组长验收要点（每岗位产出后 30 秒过一遍）
- scout：⚠️冲突情报有吗（有→全因素重审）；证据级别"传闻"当事实了吗；**数据来源=原文自读吗**（转述=打回）
- loader：缺口清单空吗（不空→WebBridge/另一源补）
- analyst：差异点给证据链了吗（没链=打回）；双向冲突摆出了吗；META 行有吗
- qc：**前提矛盾有标注吗**；挑错是"漏洞"还是"不同意见"；红色"必须改"先裁决
- archivist：反馈可溯源吗；下批建议具体吗

## 铁律（防协作翻车）
- 成员**只提供信息/推演/挑错**，不做最终判断；判断权=组长全因素+用户拍板（不变）
- 每批**复用常驻 5 人组**，禁止新建临时子代理；临时核查员用完即换届
- **情报一律原文自读（data.js 行号），禁止组长转述**（v2 铁律·001 事故根源）
- 成员输出必须带**自检行**（数据溯源+独立性确认）——没有则视为未完成
- 产出文件 UTF-8；禁数字编造；禁盘口词
