# FotMob 稳定数据获取方案（2026-08-16 验证通过）

> 背景：FotMob 公开 API 大量失效（leagues/matches/search 等 404），仅 matchDetails（数字 matchId）可用；
> 网页版为 Next.js 纯客户端渲染（普通 UA curl 无数据）。以下为验证通过的**稳定可复用方案**。

## 方案 A：联赛全赛季赛果（首选·最稳定）

```
curl.exe -s -A "Mozilla/5.0 (compatible; Googlebot/2.1; +http://www.google.com/bot.html)" \
  "https://www.fotmob.com/leagues/{leagueId}/results/{slug}?season={年}"
```

- Googlebot UA 触发 Next.js SSR → HTML 内含 `<script id="__NEXT_DATA__" type="application/json">`
- 解析路径：`__NEXT_DATA__.props.pageProps.fixtures.allMatches`（数组，380 场/联赛）
- 每场字段：`round`、`pageUrl`（含数字 matchId）、`home/away{id,name}`、`status{utcTime, finished, scoreStr}`
- 已赛判定：`status.finished == true`；比分：`status.scoreStr`（"3 - 4"）
- ⚠️ 无半场比分（ht 需另取）；season 不传 = 当前赛季
- 已验证：日职 223（2025 全季 380 场 + 2026-27 已赛 20 场）、西甲 87（2026-27 已赛）

**已知 leagueId/slug**：日职 223/j-league、西甲 87/laliga、英冠 48/championship（parentLeagueId 48）

## 方案 B：单场 matchDetails（实时/详情）

```
curl.exe -s -A "Mozilla/5.0" -H "x-mas: 9a9a7e262fce7ff04f0de2242aaf5c34" \
  "https://www.fotmob.com/api/data/matchDetails?matchId={数字id}"
```
- 数字 id 获取：方案 A 的 pageUrl#id；或 Googlebot UA curl 比赛页（/matches/{slug}/{short}#id）
- 内容：events（进球/红牌）、lineup、stats、shotmap、h2h（两队交锋史，**不能扩散全联赛**）

## 方案 D：teams API 扩散（2026-08-16 子代理验证·全赛季赛程+对手扩散）

```
curl.exe -s -A "Mozilla/5.0" -H "x-mas: 9a9a7e262fce7ff04f0de2242aaf5c34" \
  "https://www.fotmob.com/api/data/teams?id={teamId}"
```
- `fixtures.allFixtures.fixtures` 含**全赛季赛程**（对手 teamId + 比分 + reason + matchId）——从种子队扩散可覆盖联赛全部队伍（日职 20 队一次到位，~6MB 缓存）
- 比 read_page 高效（无需逐页渲染）；比分权威值 = **status.scoreStr**（见踩坑）

## 方案 E：竞彩官方赛程接口（2026-08-16 打通·权威赛程源）

```
curl.exe -s -A "Mozilla/5.0 (compatible; Googlebot/2.1; +http://www.google.com/bot.html)" \
  -H "Referer: https://www.sporttery.cn/jc/zqszsc/" \
  "https://webapi.sporttery.cn/gateway/uniform/football/getMatchListV1.qry?clientCode=3001"
```

- 页面 https://www.sporttery.cn/jc/zqszsc/ 是 SPA 空壳（read_page 无数据）→ Googlebot UA 直抓 → 从页面引用的 `jc_szsc_gz.js` 挖出接口拼装 → `commonV1.js` 找到 clientCode=3001（两网）
- 返回：`errorCode=0`；`value.matchInfoList[]` 按 businessDate 分组 → `subMatchList[]` 每场：matchNumStr（"周日011"）/matchDate/matchTime/homeTeamAbbName/awayTeamAbbName/leagueAbbName/matchStatus（Selling=在售）/matchId/oddsList
- 验证：2026-08-16 周日 28 场与网易竞彩页逐场一致（011 社区盾 22:00 等）
- ⚠️ 官方**赛果**接口 getUniformMatchResultV1.qry 2026-08-16 起全 E0001（接口已变）；赛果仍以 FotMob 为准，赛程用本接口
- 通用套路（技能 googlebot-web-capture）：read_page 拿不到 JS 渲染内容时 → curl+Googlebot UA 直抓 → 挖页面 JS 里的接口 → 带 Referer 调接口

## 已知坑

- 普通 UA curl 联赛/球队页 = Next.js 壳（无数据）；`__NEXT_DATA__` 仅 Googlebot UA 触发
- read_page 有页面缓存；season 参数在 read_page 下被忽略（curl 直接带 query 有效）
- h2h = 两队交锋史（同对局），勿用于联赛扩散
- matchDetails 的 league.id 是字符串（"223"），比较时转 int
- **⚠️ 点球大战场次：teams API 的 home.score/away.score 返回【点球比分】而非真实比分，必须用 status.scoreStr 作权威**（2026-05-16 浦和 0-0 东京 API 显示 9-10；川崎 1-1 町田显示 6-5；长崎 2-2 神户显示 5-4——已修正 3 场）
- 加时场 reason=AET 比分本身正确（Machida 2-1 名古屋）；收集其他联赛时务必检查 reason=Pen/AET 场次
- 日职 2026 为跨年实验赛制（100 Year Vision League 小组赛含点球决胜），3 场 0-0/1-1/2-2 是"点球定胜负的平局"，与普通平局统计口径不同（参数校准注意）
