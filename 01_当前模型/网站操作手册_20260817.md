## 1. 网页部署（Cloudflare Pages）—— 用户看的就是这个
- 站点根目录：`D:\Cola\足球分析学习\_发布_public`
- 部署命令（或直接运行 `D:\Cola\足球分析学习\发布报告中心.ps1`）：
  `wrangler pages deploy "D:\Cola\足球分析学习\_发布_public" --project-name football-analysis-report`
- 域名：https://football-analysis-report.pages.dev （/avoid=红黑总榜 /review=赛后复盘 /index=赛前预测）
- 缓存约 1-2 分钟生效；**部署≠GitHub 推送**（GitHub 只是备份）

## 2. 版本号防缓存（铁律，2026-08-17 教训）
- avoid.html / index.html / review.html 引用 js/css 均带 `?v=YYYYMMDDHHmm`
- **每次改 data.js / app.js / style.css，必须同步更新所有 html 里的版本号**（用真实时间 Get-Date），否则浏览器/CDN 缓存旧文件、用户看不到更新
- 版本号更新方法：`?v202608172300` → `?v{新时间}` 全文件替换

## 3. GitHub 备份（非部署，daily_backup.ps1 双仓库）
- 仓库：`D:\Cola\足球分析学习`（origin=ghfast.top 代理），备份脚本 `D:\Cola\_backup\daily_backup.ps1`
- 推送流程：备份 gitconfig → `git config --global --unset-all url.https://ghfast.top/.insteadof` → gh auth token 官方 URL 直推 → 恢复代理

## 4. 改完网页的验证清单（每次必做）
1. `node --check data.js` 和 `node --check app.js`（语法）
2. **发布前全自动核查（2026-08-20 新增）：`python D:\Cola\_tmp_football\check_batch_full.py <批次键>`**（如 2026-08-20）——自动检查五维结构合规/ht 反向标记与 scores 一致/抓鬼结论/红黑榜对照/logic 要素/欧战 R380 声明/预警覆盖，输出 check_<批次>_out.txt，0 场有问题才可发布（8/20 批 007/009 ht 反向标记不一致+002/003 抓鬼缺失教训）
3. 更新 html 版本号（见第 2 节）
4. `wrangler pages deploy` 部署
5. 等 1-2 分钟，curl 线上文件确认关键字符串（如 `curl https://football-analysis-report.pages.dev/js/data.js?v=xxx | Select-String "TEAM_RATING"`）
6. 全部通过后才告知用户"刷新查看"（提示 Ctrl+F5）

- **现状**：发布目录 2105KB→888KB；字体请求 81 分片→1 个（LXGWNeoXiHei-page.woff2 137KB）；font.css 60KB→0.6KB；font-display: swap（字体加载前先显示系统字体）
- **工具**：`python D:\Cola\_tmp_football\subset_fonts.py`（页面字符集提取→fonttools 子集化；Smiley Sans 81 分片已弃用归档至 D:\Cola\_归档_旧文件\字体分片_smiley_20260820\，原 font.css 备份 font_css_pre_subset_20260820.css）

- **验证**：字体文件是否删除看 content-type/size_download（Cloudflare 对不存在文件返回 200+index.html fallback 约 2.4KB，非 404）
