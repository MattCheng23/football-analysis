# 网站操作手册（2026-08-17 建立，防遗忘铁律）

> 目的：所有网页操作知识集中于此，key 记忆只存指针。每次操作后如有新坑，立即追加本节。

## 1. 网页部署（Cloudflare Pages）—— 用户看的就是这个
- 站点根目录：`D:\Cola\足球分析学习\_发布_public`
- 部署命令（或直接运行 `D:\Cola\足球分析学习\发布报告中心.ps1`）：
  `wrangler pages deploy "D:\Cola\足球分析学习\_发布_public" --project-name football-analysis-report`
- 域名：https://football-analysis-report.pages.dev （/avoid=红黑总榜 /review=赛后复盘 /index=赛前预测）
- 缓存约 1-2 分钟生效；**部署≠GitHub 推送**（GitHub 只是备份）

## 2. 版本号防缓存（铁律，2026-08-17 教训）
- avoid.html / index.html / review.html 引用 js/css 均带 `?v=YYYYMMDDHHmm`
- **每次改 data.js / app.js / style.css，必须同步更新所有 html 里的版本号**（用真实时间 Get-Date），否则浏览器/CDN 缓存旧文件、用户看不到更新
- 版本号更新方法：`?v202608172300` → `?v{新时间}` 全文件替换

## 3. GitHub 备份（非部署，daily_backup.ps1 双仓库）
- 仓库：`D:\Cola\足球分析学习`（origin=ghfast.top 代理），备份脚本 `D:\Cola\_backup\daily_backup.ps1`
- 推送流程：备份 gitconfig → `git config --global --unset-all url.https://ghfast.top/.insteadof` → gh auth token 官方 URL 直推 → 恢复代理

## 4. 改完网页的验证清单（每次必做）
1. `node --check data.js` 和 `node --check app.js`（语法）
2. 更新 html 版本号（见第 2 节）
3. `wrangler pages deploy` 部署
4. 等 1-2 分钟，curl 线上文件确认关键字符串（如 `curl https://football-analysis-report.pages.dev/js/data.js?v=xxx | Select-String "TEAM_RATING"`）
5. 全部通过后才告知用户"刷新查看"（提示 Ctrl+F5）
