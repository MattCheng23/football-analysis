# Agent 自我蒸馏（2026-09-07 · 用户点名批评后深度整理）

> 触发：用户 9/7 批评"踩坑过的地方反复踩坑、偶尔乱猜（把没结束的比赛当结束去抓数据）"。
> 目的：把 Agent（我）的行为弱点模式→实证→根因→对策固化，不是泛泛自我批评。
> 用法：任何"赛果/状态/接口/入库"类操作前扫一遍本文件的**触发词**；每轮收尾答"收尾自检五问"。

---

## 模式 P1 · 乱猜状态（最高危·用户点名：把未结束的比赛当结束）

- **行为指纹**：脑内推断"开赛+2h=应该结束了"→ 直接开抓/宣布赛果；或"全自动推进"时主动补抓未来场次。
- **实证**：Cola_9 turn 421（9/6 凌晨）——主动声称"013-024 的 12 场赛果已完赛我没收"，全自动抓取，被用户打断"你不要乱猜盲猜，赛果没有结束"；8/31 016/017 比赛中（34'/26'）被当赛果登记复盘。
- **根因**：①把"合理预测"当"已发生事实"（推断≠事实）②"抢先干活"的自动化冲动压过"事实核验"③复盘中赛果核验"第 0 步"存在但被跳过。
- **对策（强制四步，缺一=行为违规）**：
  1. 接口字段 `finished===true`（抓取输出必须打印，**不以时间推断代替**）
  2. 匹配预期对阵（队名校验，防页面错配）
  3. 半场=事件流 45' 前逐球脚本计算（禁推断）
  4. **凡输出"赛果/已完赛"字样，必须先引用上面的核验证据**；证据不满=标"待核/比赛中"，宁可说"待核"不说"应该是"。
- **触发词**（出现即 STOP 转核验）：`应该结束了` / `肯定出了` / `大概` / `差不多` / `我先抓吧` / `主动收`。

## 模式 P2 · 凭记忆拼模式（接口/字段/路径）

- **行为指纹**：URL 靠记性拼（缺 `/api/data/`）；字段名靠猜（`goal` vs `Goal`、`minute` vs `time`）；路径凭印象。
- **实证（9/7 全程）**：matchDetails 少了 `/api/data/` 抓回 HTML 反爬壳；事件流 `type -eq 'goal'` 零命中（实际大写 `Goal`）；`$e.minute` 不存在（实际 `time`）；PowerShell `$c = {}` 当 hashtable。
- **根因**：速查表 URL 本身不全+字段名无登记+**查表行为没有被强制**（"我熟"的错觉）。修正后机制：速查表已补全 URL/字段名（9/7）。
- **对策**：任何数据操作前 5 秒：①查 `最优通道速查表_20260825.md`（数据装载节+字段名速查节）②表里有=抄全串，禁止拼 ③表缺=先 dump 单对象全部 key 再写解析（`content.matchFacts.events.events[0] | ConvertTo-Json` 式样本）。

## 模式 P3 · 工具通过≠正确（验证链缺口）

- **行为指纹**：node --check 通过=以为没问题；单点校验≠整体校验。
- **实证**：013 入库产生 `},,` 双逗号——**node --check 竟然 exit 0**（JS 稀疏数组合法），险些漏掉；9/6 误插 evidence 数组同样单点校验未拦。
- **根因**：验证链只到"语法通过"，缺"结构断言"（数组元素数/双数组各命中/逗号健康）。
- **对策**：data.js/data-review.js 修改后验证链=**node --check → hole_guard.py（`},,` 扫描+`--expect="<键>.<数组>:<n>"` 元素数断言）→ check_batch_full**；复盘入库=results/evidence 分开插入+分别校验+hole_guard。

## 模式 P4 · 快速迭代绕过规则（明知故犯型）

- **行为指纹**：规则书里有（🔴#1 禁内联 python），实际因"就一次/很快"跳过。
- **实证（9/7）**：同一会话 **3 次** PowerShell 内联 python（GBK/ParserError/引号地狱循环），每条都撞操作经验库 🔴#1。
- **根因**：把"规则"当"建议"；效率错觉（内联看似快，实际 3 次失败 > write 文件 1 次）。
- **对策**：内联冲动出现→念"内联三败记录"（8/25 3 次+9/7 3 次）→改 write。**含中文/正则/JSON/多语句的一切脚本一律 write 文件再执行**（铁律已升级为"变种也禁"）。

## 模式 P5 · 上下文断层（会话切换丢进度）

- **行为指纹**：新会话不继承旧进度→凭猜测重建状态（本会话开局我猜"013 未处理"差点重复/跳过实际状态）。
- **实证**：9/7 用户新建会话（Cola_9.7），我开局靠记忆+文件 mtime 推断，被用户纠正"直接找到 Cola_9 内容完整继承"（实际真源=session_projcache JSON+data-review.js+蒸馏日志）。
- **根因**：进度无"单点真源"；跨会话无强制接续协议。
- **对策（每次批次开新会话/恢复时强制）**：①读进度单 `_tmp_football\<批次>_progress.md`（本次建立机制：每场复盘/部署后追加一行）②读 data-review.js 该批 results/evidence 末几位确认已复盘到哪 ③读记忆 daily/project recent 10 条 ④以文件真源为准，**凡三者冲突=以 data-review.js+进度单为准并报告冲突**，禁自作主张。

## 模式 P6 · 过度自动化冲动（动作前置条件不满就先动）

- **行为指纹**：用户说"全自动做"→ 我抢跑未满足条件的步骤（如未出赛果就抓赛果）。
- **实证**：同 P1 turn 421；另有多轮"直接开抓"替代"先问状态"。
- **根因**：把"用户要自动化"误解为"我要自己找活干"。
- **对策**：自动化=**事实前置条件全部满足才触发**（赛果=finished 核验；赛前列队=官方排期+信息齐；复盘入库=双源核验通过）。前置不满=报"待满足条件"并停止，不自动脑补下一步。

## 三类强制卡（操作前扫一眼）

### 卡 A · 赛果/状态类（任何"赛果出来了/已完赛"表述前）
- [ ] finished===true 已从接口打印（非时间推断）
- [ ] 队名与预期对阵匹配
- [ ] 半场=45' 前事件流脚本计算
- [ ] 双源（API+WebBridge 渲染）比分一致才登记
- [ ] 输出含"赛果"字样的句子都带核验标记（已核验/待核）

### 卡 B · 接口/解析类（每次写 curl/python 解析前）
- [ ] URL 全串抄自速查表（含 /api/data/、x-mas 头）——禁拼
- [ ] 字段名=速查表字段名节，或已 dump 单对象确认
- [ ] 解析脚本=write 文件（非内联）；subprocess encoding="utf-8"
- [ ] 输出文件存在且大小>0

### 卡 C · 数据文件修改类（data.js/data-review.js）
- [ ] 修改前备份（auto_bak 每日一份）
- [ ] 幂等标记（已存在=SKIP；count==1 断言）
- [ ] node --check + **hole_guard.py**（双逗号+元素数）
- [ ] 复盘入库=双数组分别插入+分别校验
- [ ] bump（真实时间 Get-Date）→ deploy → 线上 curl/WebBridge 验证 → 告知刷新
