### 2.2 为什么否决批量剪枝：判据是假阳性制造机

`memory_prune.py` 默认判据 `已废弃|已撤销|已被替代|已被 V\d|作废|已过时|不再适用|勿再引用|已失效`，只读预览共命中 **13 条**（全局 4／项目 8／KEY 1）。**逐条复核后，真废弃 = 0（全局）／0（KEY）／约 5（项目，且项目轨无 archive 通道）**。

典型假阳性（这些恰恰是**最权威**的条目）：

| 命中位置 | 命中词 | 实情 |
|---|---|---|
| 全局 #42 | 「旧条目已被替代」 | 本条即《大比分覆盖口径·**最终生效版**》，是唯一口径 |
| 全局 #1 | 「已废弃」 | 指 *mnemon* 已废弃——本条是**有效禁令** |
| 全局 #77 / 项目 #356 | 「已过时」 | 指*另一条旧记忆*过时——本条是**修正令** |
| KEY #22 | 「已被替代」「已撤销」 | 本条是《记忆整理规程》，在**立规矩** |
| 全局 #89 | 「已被替代」 | 在描述「唯一口径横幅」这一机制本身 |

**根因**：检测器匹配的是「条目**引用**了被废弃的东西」，而非「条目**自述**自己已废弃」。二者在中文记忆里几乎无法靠关键词区分——所以**判据本身不可修**，只能降级为人工复核辅助（`--context` 只读预览仍有价值）。

### 2.3 铁律：记忆文件禁外部改写 → 剪枝器已封存

项目日志 2026-09-11 条目原文：「**新铁律：记忆文件（含项目日志）禁外部改写**——实测会破坏插件条目索引使 list 退化为单块；轮转/折叠改走插件 Memory Tab 或 API」。

源码核实（`dsh-memory-evolve\lib\sync\entryid.js` L90）：条目身份证 `[id:xxxxxxxx]` 由 `sha1(normalizeContent(entry))[:8]` **按内容派生**（legacy 条目），外部改写会让既有 id 引用（`expand`／归档指针／书签）整批失效。

**处置**：`D:\codex\tools\memory_prune.py` 文件头已加 ⛔ 封存段（两条独立理由 + 正路指引），保留只读 `--context` 模式。**该文件是 Codex 的写域，本次为安全加封条，已同步告知（见 §七）**。

- id: tool-workflow
  disabled: true

### 3.2 机制（源码级）

- `dsh-base\cordis.patch.yml` L336–413 在**宿主树**里注册了 `tool-ralph`／`tool-workflow`／`tool-subagent-fork` —— profile patch 关掉的是**这些宿主行**。
- `dsh-agent-presets\presets\standard\agent.cordis.yml` L193/227/230 在 **agent 平面**（`delegation` 组内）**另外注册了同名 id**，且**没有** `disabled`；profile patch 够不到这一层。

→ 结论：**禁用工具必须改预设组合（`agent.cordis.yml`），改 profile patch 等于没写。**
